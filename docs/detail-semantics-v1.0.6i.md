# v1.0.6i：详情数据目标语义与审计范围

## 范围

本阶段收口进程详情和工作组详情在目标从最新快照消失时的状态语义，并让进程操作记录的实际范围对用户透明：

- 详情状态解析显式接收当前详情目标是否存在于最新快照；目标缺失时不再显示“当前采样”或“当前采样部分可用”；
- 为目标缺失增加可测试的保留原因和一致的状态文案，保持仍可观察的上次快照与“目标已离开当前快照”的正文不矛盾；
- 将进程详情中的“最近操作记录”标注为全局记录，并说明审计日志不保存 PID、启动时间和路径，不能按当前进程精确筛选；
- 为进程和工作组两条详情路径补充纯值回归测试，覆盖目标缺失但全局仍有其他条目的情况。

## 非目标

- 不向 `ProcessActionAuditEvent` 增加 PID、启动时间、路径或其他身份指纹，也不尝试按进程名推断归属；
- 不改变进程操作的授权、身份复核、信号发送和审计持久化策略；
- 不修改采样器、历史存储、工作组归因、采样时间容忍度或菜单栏整体滚动布局；
- 不启动、终止或注销现有桌面实例，不修改正式 Application Support、登录项或 TCC/隐私权限；
- 不把当前桌面会话无法稳定暴露的 AX 详情树结果宣称为实机验收通过。

## 架构

1. `MonitorDetailDataStatus.resolve` 增加 `targetPresent` 输入。目标缺失优先于当前/部分采样判定：若仍有保留条目，返回新的 `targetUnavailable` 保留原因；否则返回 `unavailable`。这样全局采样质量不会覆盖单个详情目标的可用性。
2. `MonitorViewModel.detailDataStatus` 保留统一的采样元数据入口，并由进程详情传入 `model.process(for:) != nil`、工作组详情传入 `model.group(for:) != nil`。详情视图继续使用同一个状态视图，避免两套文案分叉。
3. 状态视图为 `targetUnavailable` 提供明确解释，保留快照仍可用于观察但不代表目标当前存在；目标消失正文继续禁止任何操作入口。
4. 进程详情的审计区显示“最近操作记录（全局）”及隐私范围说明。事件列表仍按现有时间顺序和数量限制展示，不引入错误的名称过滤。

## 风险

- 目标存在性来自当前快照，采样在详情渲染期间可能再次变化；状态应保持保守，不能据此放宽操作控制器的最终身份校验；
- 工作组可能仍存在但部分成员消失，工作组目标与成员可见性是两个层级，本阶段只修复工作组目标本身消失的语义；
- 新文案会增加详情高度，需保持现有自适应滚动和关闭入口布局；
- 旧调用方若遗漏新参数，编译器应直接暴露问题，不提供会默认为“存在”的隐式兼容路径。

## 验证标准

- `MonitorDetailDataStatus` 单元测试证明：目标缺失且全局仍有条目时不会得到 `.current`/`.partial`，并返回 `.targetUnavailable`；目标存在时既有状态保持不变；
- 进程和工作组详情调用点分别传入正确的目标存在性；审计范围文案与事件模型的隐私字段约束一致；
- `swift test --package-path . --parallel`、严格并发 Debug/Release 构建、`./scripts/verify-release.sh`、`git diff --check` 全部通过；
- 不修改既有未跟踪探针/临时目录、正式实例或正式存储；真实详情页 AX 验收仍单独记录为未验证或待稳定桌面会话复核。

## 分阶段交付

1. **设计契约**：提交本文档，冻结范围、状态优先级和审计透明度要求。
2. **源码与测试**：修改状态模型、详情调用点和审计文案，补充回归测试后单独提交并推送。
3. **验证记录**：完成 targeted/full tests、严格构建和发布脚本检查，新增验证记录并单独提交、推送。
4. **后续 v1.0.6j**：另行处理菜单栏外层可达性和登录启动状态订阅，不与本阶段混合。
