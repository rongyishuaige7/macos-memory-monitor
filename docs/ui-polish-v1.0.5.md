# v1.0.5 界面与交互修整

## 范围

本批次针对真实菜单栏运行时暴露的可用性问题，优先修整不需要改变采样模型的界面交互：

- 为菜单栏面板提供明确、可达的退出入口，并继续复用现有优雅关闭协调器；
- 核对进程详情中的工作组区块，避免重复渲染；当前源码保持单一调用；
- 为新增入口和现有图标按钮补齐可访问名称，避免只显示图标时无法判断用途；
- 保持实时/历史、健康检查、登录项和进程操作的现有语义不变。

## 非目标

- 不改变采样频率、进程信号策略、历史存储格式或登录项默认状态；
- 不自动注销、重启、结束其他进程或修改 macOS 权限；
- 不在本批次重做整体视觉主题或引入新的第三方依赖；
- 不把尚未由用户完成的重新登录行为写成已验证结论。

## 架构

退出动作只调用 `NSApplication.shared.terminate(nil)`，由现有
`MemoryMonitorApplicationDelegate.applicationShouldTerminate` 进入
`ApplicationTerminationCoordinator`，等待历史和审计收尾后再回复 AppKit。
退出按钮放在面板 footer，状态项 label 同时提供上下文菜单作为快捷路径；两条路径共享同一个动作，避免产生不同的关闭语义。

## v1.0.5a 实现记录

- 新增可注入的 `ApplicationTerminationAction`，默认实现仍为
  `NSApplication.shared.terminate(nil)`，并由状态项右键菜单、header 的更多菜单
  和 footer 的可见按钮共同调用。
- 健康诊断、操作审计、筛选/排序和详情关闭等图标控件补齐无障碍名称；状态项
  同时提供可读的状态标签和值。
- 对 `ProcessDetailView` 的工作组区块重新核对源码，当前只有一次
  `groupSection(process)` 调用，因此没有为了疑似重复而删除有效内容。
- 新增退出动作的注入测试；全量测试由 233 项增至 234 项。

## 风险

- `MenuBarExtra` 的 `.window` 样式在不同 macOS 版本对状态项右键上下文菜单的支持可能不同，因此面板内的文字/图标退出按钮必须独立可用；
- 终止动作会触发真实应用关闭，验证时不得对当前用户的其他进程发送信号；
- 固定宽度面板中的新增控件可能压缩底部诊断文案，需要在 arm64 实机截图检查。

## 验证标准

- `swift test --parallel` 全部通过，并新增测试覆盖退出动作调用；详情区块结构由源码静态复核；
- Debug/Release 构建、签名和桌面诊断结构校验通过；
- 运行中的菜单栏面板能看到退出入口，点击后应用完成历史/审计收尾并退出；
- 右键状态项若系统支持上下文菜单则显示退出项；即使不支持，面板内入口仍可用；
- 不改变当前 c3c 桌面验证报告的既有含义。
