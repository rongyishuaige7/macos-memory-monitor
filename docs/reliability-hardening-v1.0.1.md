# v1.0.1 可靠性加固设计

## 范围

本阶段处理采样、历史和进程操作状态机中会导致错误数据、错误建议或丢失安全操作入口的问题：

- 区分进程扫描是否尝试、是否成功以及结果是否可用，并在失败时按重试策略重新扫描；
- 对空结果、低覆盖率结果和系统采样失败保留最近一次可用的进程/工作组快照；
- 只有与当前系统采样同一时刻的新鲜工作组快照才写入历史，避免时间错位；
- 让优雅退出超时、取消和后续强制结束请求保持可证明的状态转移；
- 让趋势分析对重复组标识、非有限数值和无效时间间隔保持确定性；
- 让损坏的快照文件不会阻断仍然有效的 journal 恢复。

## 非目标

- 本阶段不重写工作组归因规则、Safari/WebKit 识别器或建议阈值；
- 不改变公开隐私策略、历史格式版本或 UI 信息架构；
- 不引入第三方依赖，不调整采样频率的产品策略，不实现远程监控；
- 不在没有用户明确授权的情况下执行 kill、删除数据或推送外部仓库。

## 架构与状态变化

采样层继续返回一个不可变 `MonitorSnapshot`。应用层使用三类状态：

1. `attempted`：本轮是否执行了进程枚举；
2. `successful`：枚举和条目读取是否完成且没有底层错误；
3. `usable`：结果覆盖率和条目质量满足替换当前快照的条件。

`MonitorViewModel` 只在 `usable` 为真时替换进程和工作组，并把最近一次成功时间交给采样策略；失败或不完整结果只更新诊断，不清空旧数据。历史记录携带与系统采样配套的工作组快照时间；没有同轮新鲜快照时写入空归因或沿用明确标记为旧的记录，不能把缓存组伪装成当前时刻数据。

进程操作状态机将 `timedOut` 视为仍占用目标的终态。任何异步发送/等待完成后都校验操作 token 和取消状态，过期任务不得覆盖新状态；超时目标只能通过对应身份的二次确认进入强制结束。

趋势分析先规范化输入：过滤非有限时间/footprint、拒绝非正间隔，并以确定的组 ID 聚合后再计算增长率。历史加载分别处理快照和 journal，快照无效时仍尝试恢复有效 journal。

## 风险

- 保留旧进程快照会让已退出进程短时间继续显示，因此 UI 必须显示采样年龄/受限提示；
- 低覆盖率阈值过严会降低刷新率，过松则可能再次清空有效数据；阈值以现有采样诊断和测试样本校准；
- 历史格式兼容性必须保持，新增字段使用可选解码或默认值；
- token 校验只能约束应用内状态，不能消除操作系统 signal 与 PID 复用之间的全部 TOCTOU 风险。

## 验证标准

- SwiftPM 全量测试通过，并新增覆盖 provider 错误/空估算结果、取消挂起中的 graceful、超时后新请求、重复组 ID、NaN/零间隔和损坏快照+有效 journal 的回归测试；
- Debug/Release 严格并发构建通过；
- `memory-monitor-probe` 能运行并报告采样质量；
- app bundle 构建、签名校验和 `git diff --check` 通过；
- 失败采样不会清空最近成功进程/工作组，且下一个进程采样不会被错误延迟到完整后台周期之后；
- 超时目标不会被新 graceful 请求覆盖，取消不会遗留 `waiting`/busy 状态；
- 趋势结果不包含 NaN/无穷增长率，历史 journal 可在快照损坏时独立恢复。
