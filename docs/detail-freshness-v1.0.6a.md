# v1.0.6a 详情页数据新鲜度

## 范围

本批次处理详情窗口中“当前快照”和“保留旧数据”容易混淆的问题：

- 为进程详情和工作组详情显示当前进程采样是否实时、部分可用或来自上次成功采样；
- 在采样未刷新时保留可观察数据，但明确提示其时间语义，避免把旧快照当作当前状态；
- 将新鲜度判断提取为可测试的纯值模型，覆盖首次加载、完整采样、部分采样、后台跳过和采样失败；
- 不改变进程操作控制器的最终身份复核和信号策略。

## 非目标

- 不改变采样频率、历史存储格式、进程分组或建议引擎；
- 不因为快照变旧就静默发送或阻止任何信号，实际操作仍由现有策略和二次身份校验决定；
- 不启动、终止或注销现有桌面实例，不修改 TCC、登录项或用户文件；
- 不引入第三方依赖或重做详情窗口的整体视觉主题。

## 架构

新增 `MonitorDetailDataStatus` 纯值类型，由进程采样状态、采样诊断、保留条目数量和观察时间解析详情页状态。状态优先级为：

1. 当前完整/可用采样；
2. 当前采样存在但覆盖率受限；
3. 本轮跳过进程扫描但仍保留上次数据；
4. 采样失败或尚未完成首次采样。

详情视图只消费该状态并展示紧凑提示，不复制采样判断逻辑。状态文案明确“可观察”和“可操作”是两件事：操作按钮仍由 `ProcessActionController` 在发送边界重新读取并校验进程身份。

## 风险

- `SampleStatus.sampledAt` 可能缺失或来自异常时钟，纯模型必须在非有限日期下回退到保守状态；
- 后台模式有意跳过进程扫描，不能把 `unavailable` 文案误报为采样失败；
- 详情窗口宽度有限，提示必须限制布局高度且不挤压现有操作控件。

## 验证标准

- 新增单元测试覆盖每种状态及边界（无保留条目、非有限时间、部分采样）；
- `swift test --package-path . --parallel` 全部通过；
- Debug/Release 严格并发构建通过；
- 在独立 UI-check bundle 中确认进程/工作组详情出现状态提示，且现有退出入口和操作确认流程不受影响；
- c3c 实例及其 evidence 目录不被启动、终止或修改。

## 分阶段交付

1. **v1.0.6a**：新鲜度值模型、详情页提示和单元测试。
2. **后续**：单独评估详情页操作按钮在更窄窗口、较大字体和长本地化文本下的自适应布局。
