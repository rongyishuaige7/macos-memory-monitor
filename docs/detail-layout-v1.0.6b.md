# v1.0.6b 详情窗口自适应布局

## 设计判断

这是面向开发者的原生 macOS 监控工具详情面板，属于高密度产品 UI。当前批次采用保守的 SwiftUI 原生布局演进：保持现有信息架构、中文文案和窗口尺寸，优先保证窄宽度、较大字体和长值仍然可读。

## 范围

本批次审计并优化进程详情和工作组详情：

- `DetailInfoRow` 的固定标签列和长值布局；
- 父进程链、工作组成员、操作记录中带尾部值的单行 `HStack`；
- 进程操作按钮在多个按钮同时出现时的压缩和可达性；
- 进程/工作组指标网格在可用宽度变化时的列数；
- 进程详情最小宽度 500、工作组详情最小宽度 540 下的源码和实机表现。

## 非目标

- 不改变详情窗口的最小/理想尺寸、sheet 路由或信息架构；
- 不改变进程采样、分组、历史记录、建议引擎或操作身份校验；
- 不引入第三方依赖，不重写整体视觉主题；
- 不因为布局不足而隐藏、删除或静默改写进程数据；
- 不启动、终止或修改已有桌面实例、c3c 实例或其 evidence 目录。

## 审计基线

当前实现存在以下结构性风险：

1. `DetailInfoRow` 用 78pt 固定标签宽度，值区只有一行横向空间；长本地化标签会挤压值，窄窗口时容易只剩截断文本。
2. 父进程、成员和操作记录行都把主文本、尾部 PID/状态/时间放在同一个带 `Spacer` 的单行 `HStack` 中。SwiftUI 压缩时主文本可能先变成不可识别的短片段，尾部信息也可能互相覆盖。
3. 进程操作按钮固定在单行 `HStack`。优雅退出、强制结束和取消同时可见时，较大字体或较窄宽度会压缩按钮标签，降低可达性。
4. 指标网格固定为两列；当详情内容区域进一步变窄时，标题和说明只能依靠单行截断，信息层级不稳定。
5. 详情正文虽然位于 `ScrollView` 中，但这些横向布局没有明确的纵向回退策略，放大字体后无法保证每个值都有可读的替代排列。

## 架构

- 新增纯值布局策略，使用可用宽度、标签最小宽度、尾部值宽度和控件数量判断何时从横向切换为纵向；策略不依赖 AppKit 窗口状态，可单元测试。
- 详情行使用 `ViewThatFits(in: .horizontal)`：优先保留紧凑横向排列，无法容纳时切换为标签在上、值在下的纵向排列；纵向值允许自然换行。
- 带尾部值的关系/成员/审计行保留相同信息顺序，横向候选不适配时使用两行结构，确保 PID、状态和时间仍可见。
- 操作按钮在横向候选不适配时改为纵向按钮列，按钮动作和禁用条件保持不变。
- 指标网格使用自适应最小列宽，在更窄内容区域自动降为单列。

## 风险

- `ViewThatFits` 的测量受 macOS 版本和 Dynamic Type 影响，必须同时做严格并发构建和独立 bundle 的 AX 检查。
- 横向候选使用固定尺寸测量来判断是否适配，长路径可能更早切到纵向，代价是详情高度增加但信息更完整。
- 纵向回退会增加滚动高度；这是可接受的布局变化，因为详情正文已有滚动容器。
- 不同字体设置下按钮宽度可能不同，验收应检查按钮可见、可启用和顺序，而不是依赖像素坐标。

## 验证标准

- 新增布局策略单元测试，覆盖阈值边界、非法/无限宽度、零按钮和多按钮情况；
- `swift test --package-path . --parallel` 全部通过；
- Debug/Release 严格并发构建和 `scripts/verify-release.sh` 通过；
- 独立 UI-check bundle 中分别检查进程详情和工作组详情：最小宽度下无横向遮挡，详情行值可读，父链/成员/趋势仍可见，操作按钮（如有）可达；
- 在可用的辅助功能树中确认详情状态、按钮标签和关闭入口仍存在；
- 不操作正式 c3c 实例，不修改现有 evidence 目录。

## 分阶段交付

1. **文档审计**：记录现状、风险、策略和验收标准。
2. **自适应布局**：新增布局策略与详情控件回退，补充纯值测试。
3. **验证交付**：完成全量测试、构建、独立 UI-check，更新本记录并提交推送。
