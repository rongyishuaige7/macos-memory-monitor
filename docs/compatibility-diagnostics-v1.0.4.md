# v1.0.4 兼容性诊断

## 范围

把运行环境本身纳入“运行健康”快照，明确展示：

- 当前 macOS 主/次/修订版本；
- 当前 CPU 架构；
- 是否满足应用声明的 macOS 14+ 最低版本；
- 是否属于当前 App bundle 发布目标的 arm64 架构。

该状态只作为诊断信息，不改变采样策略或进程操作授权。

## 非目标

- 不声称一次本机运行覆盖所有 macOS 版本；
- 不在应用内自动申请权限、切换架构或安装 Rosetta；
- 不改变 `libproc`、IOAccelerator、ServiceManagement 或 audit-token 的调用方式；
- 不把 x86_64 环境标记为绝对不可运行，除非平台本身低于最低 macOS 版本；
- 不记录主机名、用户名或其他设备识别信息。

## 架构

`RuntimeEnvironmentStatus` 是不持久化的值类型，由 App 层在生成健康快照时读取 `ProcessInfo` 和编译架构。健康评估器把它映射为一个独立的“运行环境”条目：macOS 低于 14.0 时为需要处理，非 arm64 时为部分可用，满足两项时为正常。测试可以注入确定的环境值，不依赖测试机实际版本。

v1.0.4b 增加独立的兼容性采集入口。`memory-monitor-probe --compatibility-json` 输出带 schema 版本的 JSON，只包含产品版本、源码 revision、macOS 版本、进程架构、各采集源质量、耗时和进程覆盖率。报告不包含主机名、用户名、序列号、PID、进程名、路径、工作组或内存内容。`scripts/collect-compatibility-report.sh` 负责从 `Info.plist` 和 Git 注入产品元数据并校验 JSON；默认写到标准输出，由调用者明确决定保存位置。

自动报告只验证无副作用的采样路径。登录项注册、系统设置中的权限变化和 audit-token 绑定发信号都保持为 `not_run` 限制项，不能因为 JSON 生成成功就标记为通过。每台真实主机或虚拟机生成一份报告，矩阵汇总在独立文档中进行，避免脚本覆盖或伪造其他系统版本的结果。

v1.0.4c 使用 GitHub 托管的 macOS arm64 runner 补齐最低系统版本附近的自动证据。独立兼容性门禁在 macOS 14 和 macOS 15 上运行全量测试、严格并发构建、人类可读 Release probe 和结构化报告采集，并把每个 runner 的脱敏 JSON 作为短期 CI artifact 保存。该门禁不构建或签名正式 App bundle；arm64 bundle、版本一致性和签名仍由本机 `scripts/verify-release.sh` 验证，避免把虚拟化 CI 环境误写成桌面发布验收。

## 风险

- 编译架构反映当前二进制，不代表用户是否安装了另一份架构的 App；文案必须使用“当前进程架构”和“发布目标”而非绝对兼容承诺；
- macOS 版本字符串来自系统 API，格式化时要避免非有限或负数值污染诊断；
- 兼容性条目只能说明平台前置条件，不能替代跨版本实机回归。
- JSON 报告可能包含系统错误文本；只允许写入内部采样器生成并经过长度与控制字符清理的消息，不接受任意外部命令输出。
- Git revision 只能证明报告声明的源码基线；工作区有已跟踪改动时必须同时记录为 `modified`，不能伪装成对应提交的发布结果。
- GitHub 托管 runner 是短生命周期虚拟环境，GPU、进程覆盖率和 ServiceManagement 行为可能与真实登录桌面不同；矩阵必须标明证据来源，不能把 CI 结果外推为所有设备通过。
- GitHub 已宣布 macOS 14 runner 将在 2026-11-02 退役；当前自动矩阵只能在退役前采集该环境，之后最低版本回归需要自托管或其他真实 macOS 14 主机。
- CI artifact 有保留期限，只用于复核当次结构化结果；长期结论必须把脱敏摘要和对应 workflow run 写入矩阵文档。

## 验收标准

- 健康面板包含运行环境条目，并显示版本、架构和支持级别；
- 注入 macOS 14 arm64、macOS 13 arm64、macOS 14 x86_64 三种值时，状态分别为正常、需要处理、部分可用；
- 不提供环境值的旧测试输入仍保持原有健康条目行为；
- 兼容性 JSON 可以被 `plutil` 解析，包含 schema、产品、平台、采样和明确限制项；
- JSON 编码测试证明进程 PID、名称、路径和用户标识不会进入报告；
- 采集脚本不接受隐式持久化目录，不修改登录项、TCC、应用安装或进程状态；
- macOS 14/15 arm64 自动门禁确认实际系统主版本和进程架构与矩阵声明一致，并为每个环境产出可解析的 schema 1 报告；
- 自动门禁允许 GPU 或部分进程在虚拟环境中受限，但必须确认系统采样有效、进程扫描确实执行且三项副作用限制仍完整存在；
- CI 报告使用显式输出路径，工作流权限限制为只读仓库内容，报告 artifact 不包含进程身份或设备标识；
- 全量 Swift 测试、Debug/Release 严格并发构建、Release probe 和发布验收脚本通过；
- 不产生持久化文件或系统设置变更。

## 分阶段交付

1. **v1.0.4a**：值模型、健康评估映射和注入测试。
2. **v1.0.4b**：结构化脱敏报告、可重复采集脚本和当前主机基线。
3. **v1.0.4c1**：建立 macOS 14/15 arm64 的只读自动门禁和脱敏 artifact，不提前写入兼容结论。
4. **v1.0.4c2**：复核实际 workflow 报告，把 runner 来源、run 和真实采样摘要写入矩阵。
5. **v1.0.4c3**：在真实桌面会话验证登录项、权限状态和专用测试进程的 audit-token 路径。
6. **后续发布阶段**：根据矩阵决定是否扩大架构支持或调整发布声明。
