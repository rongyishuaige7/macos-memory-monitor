# v1.0.5b 列表状态与布局修整

## 范围

本批次收口菜单栏面板中“没有列表条目”时的反馈，并降低固定高度对信息密度的影响：

- 区分首次加载、后台本轮未扫描、采样失败、有效采样但无可展示条目和筛选后无匹配；
- 进程排行与工作组排行共用同一套空状态语义，避免把筛选结果误报为采集失败；
- 列表滚动区域使用稳定的最小/最大高度，内容少时减少无意义空白，内容多时保持可滚动；
- 保持采样、历史、权限和进程操作逻辑不变。

## 非目标

- 不改变采样频率、覆盖率阈值、排序规则或工作组归因；
- 不引入第三方依赖，不调整菜单栏面板的整体信息架构；
- 不启动或终止当前运行中的 c3c 实例，不注销或修改系统权限。

## 设计决策

空状态的优先级按用户意图排列：有搜索词或非“全部”范围时，空列表首先解释为“没有匹配”；没有筛选时，再根据本轮是否执行扫描、状态质量和是否存在保留数据选择加载、失败或无条目文案。失败信息保留采样源提供的诊断，但不会把旧数据伪装成当前数据。

进程列表和工作组列表的滚动容器采用 `minHeight`/`maxHeight` 约束，不根据当前条目数改变外层面板宽度或其他控件位置；空状态使用较小的最小高度，避免列表为空时占据完整排行高度。

实机检查补充发现：footer 原本把长诊断文案、平台标签和退出按钮放在同一行，
在 410pt 面板宽度下按钮会被压缩到不可见。因此 footer 改为两行布局，退出按钮
拥有独立的水平空间；诊断文本允许尾部截断，但不再影响退出入口的可达性。

## 风险与验证

- SwiftUI 在 `MenuBarExtra` 窗口样式下对可伸缩 `ScrollView` 的测量可能因 macOS 版本不同而变化，因此必须通过 Debug/Release 构建，并在新 bundle 上做至少一次面板布局检查；
- 纯状态决策通过单元测试覆盖，保留现有全量采样与生命周期测试作为回归保障；
- 本批次不以 c3c 的历史桌面证据代替新 UI 的人工验证。
