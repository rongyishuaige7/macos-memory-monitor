## 必须守住的边界

1. 未知/过期不显示正常；失败/不完整检查不显示为零候选成功。
2. 清理请求对象必须是本次冻结、未过期预览中用户确认的完整身份子集。
   取消不补位，旧任务不启动新操作；仍逐项复验，默认无授权、最多八个。
3. 保留完整授权、PID+启动时间、CPU/近期活动/前台保护、互斥、审计门闩、
   worker token 与预算。执行中撤销继续有效，不为性能优化省略安全采样。
4. “已请求退出”与“已确认退出”分开；停止不撤销已发请求，内存波动不冒充
   精确释放。历史归因不从当前进程补造，不从历史直接操作同名应用。
5. 本轮诊断只读，不自动恢复/清空数据。缺 `currentFiles` 的旧事务继续
   人工恢复；摘要只含白名单，新文件 0600，拒绝覆盖，不上传真实记录。
6. 生产 UI fixture 的执行总闸保持关闭。真实退出验证仅限专用测试子进程，
   截图使用临时 fixture，不修改真实用户数据或已安装应用。

不迁移登录项、不修改 TCC/签名资质，不执行真实登录/注销，不 bump 版本、
不部署或发布。macOS 14、Developer ID/公证等外部条件按 S7 记录保留，不能
把 macOS 15 结果外推到 14，也不因此停止独立的 UX 编码工作。

## 验证和交付

测试命令和 A01–A18 完整矩阵见主方案第 11 节。每片做比例合适的验证，
最终运行完整 `verify-release.sh`，保留新证据目录、四套独立原生日志和 CI。
不能用 skipped native、测试数量下限或历史 S7 证据宣称本次全绿。
最终门禁在代码/验证输入已提交且工作区干净时运行；随后仅补交付文档时，
保留产物的实际源码提交，不把文档 HEAD 改标为构建来源。

GUI 会话或其他环境阻塞时保留失败和未运行状态，继续独立工作；仍有必要
验证未完成时，报告实现进度和限制，不标记整个候选验收完成。不要绕过
当前权限/入口配置，不覆盖旧证据，不把失败静默改为通过。

每片交付报告包含阶段、行为变化、提交与 push、实际验证、证据位置、
剩余限制，并更新主方案第 12.2 节。最终新建
`docs/product-experience-delivery.md`，记录实现源码、版本、门禁/CI/来源、
桌面走查与性能对照。确认工作区和本次测试进程状态后交付。
