# v1.0.3 可靠性加固设计

## 范围

本阶段修复终审确认的时间、持久化、生命周期、历史语义和进程操作问题：

- 使用真实采样时间做数据校验，把保留窗口锚点留在持久化层内部处理；
- 让排队刷新在真正开始采样时重新取时，并让压力防抖拒绝失败或长空窗形成的伪连续证据；
- 为持久化文件、JSONL 单行和 JSON 嵌套增加硬边界，让文件锁有超时并消除正常采样的整文件同步热点；
- 统一使用保留亚秒的时间编码，同时继续读取旧版整秒 ISO-8601 数据；
- 增加显式、有界的应用退出协调，排空历史和进程操作审计；
- 在历史中保存进程库存完整度，并按真实 workload 观测序列生成事件；
- 为建议保存最后确认时间、来源失效规则和 TTL；
- 把进程身份的最终复核推进到信号发送边界，保留目标消失后的取消入口，并让审计具备写前意图和失败重试；
- 修正审计发布、workload 质量排序、登录项错误恢复和 freshness marker 相对时间契约。

## 非目标

- 不改变默认采样频率、24 小时历史和 7 天审计保留策略；
- 不引入数据库或第三方依赖，不迁移到 XPC/helper 架构；
- 不承诺 macOS 对所有受保护进程都能提供内核绑定身份；无法证明强杀目标身份时应拒绝操作；
- 不重做菜单栏信息架构、归因规则或建议文案体系；
- 不删除现有历史、审计、归档、构建产物或用户实验文件。

## 架构

`MonitorViewModel` 把刷新请求时间仅用于代际和排序。生产刷新在历史预加载完成后读取新的采样时间；显式测试时间仍通过可注入时钟保持确定性。`HistoryStore` 接收真实校验时间，并继续使用自己的持久化 clock anchor 计算 retention reference。压力 evaluator 累积相邻有效观测的经过时间，失败或超过最大间隔时丢弃 pending 候选但保留 stable 状态。

持久化层在打开文件后以 `fstat` 验证大小，限制 JSONL 单行和解析深度，并用文件 identity/size/mtime generation 跳过未变化文件的全量重载。锁获取改为非阻塞重试、单调截止时间和取消检查。所有新时间使用带小数秒的 RFC 3339 编码，解码器兼容旧整秒格式。

应用退出由 AppKit delegate 返回 `terminateLater`，调用幂等 `shutdown()`，在有界时间内停止刷新、合并 fallback、flush 历史并排空审计。历史 workload payload 携带完整度；分析器从完整且 marker 严格递增的观测构建独立序列。建议保存 `lastConfirmedAt` 和所需来源，来源无法确认时只在 TTL 内保留。

进程操作在最终发送边界再次绑定身份。可取得 audit token 时使用内核绑定信号；无法取得时，优雅退出可按保守策略降级，强制结束拒绝发送。审计先写用户确认意图，再写发送和终态；失败事件保留固定 ID 并在后续操作及 shutdown 重试。目标离开当前进程列表时，UI 仍提供停止跟踪，但不开放强制结束。

## 风险

- 文件 hard cap 过小会拒绝合法历史；阈值必须明显高于默认 24 小时、40 workload 的实际规模，并暴露明确诊断；
- 文件 generation 只能作为锁内变化检测，任何绕过锁的外部改写都必须通过 inode/mtime/size 变化触发完整重载；
- 新时间格式必须同时覆盖 snapshot、journal、clock 和 audit，混合版本文件需可读取；
- workload 完整度对旧文件未知，旧记录不得被误当成完整观测；
- 退出超时必须最终允许应用退出，不能因损坏文件或被暂停实例永久挂起；
- audit-token API 的系统版本、权限和发布兼容性需实机验证，失败路径必须保持 fail closed；
- 写前审计会让一次用户操作产生多个阶段记录，UI 需要保持可读且不能把“已确认”误写成“已发送”。

## 验证标准

- `swift test` 全量通过，并保持 Swift 6 严格并发构建通过；
- 覆盖 35 分钟/8 小时前跳、25 小时/7 天回退、排队 301 秒和压力 pending 后失败/长空窗；
- 覆盖超限 snapshot/journal/audit/clock、超长行、深层 JSON、持锁超时和取消；
- 用默认规模历史证明同一 actor 的普通 append 不再重复整文件解码，并覆盖多 actor 外部 generation 变化；
- 覆盖新旧时间格式混读以及同一分钟 `t+20.1`、`t+20.9` 的跨 actor 合并；
- 覆盖 shutdown 同分钟更新、fallback 合并、flush 失败和 termination 超时；
- 覆盖 partial-complete、fresh-nil-fresh、相同 marker 和超时 marker 的 workload 事件；
- 覆盖建议持续确认、来源失败、TTL 到期和 UI 陈旧时间；
- 覆盖发送边界身份替换、audit-token 失效、gone view 取消、审计写前失败和后续重试；
- `git diff --check`、Debug/Release 构建、probe、app bundle 和签名检查通过。

## 分阶段交付

1. **v1.0.3a 时间契约**：真实校验时间、排队刷新重取时、压力连续证据。
2. **v1.0.3b 存储边界**：文件/JSON 限制、锁 deadline、generation 快路径、亚秒时间。
3. **v1.0.3c 生命周期与历史语义**：显式 shutdown、workload 完整度/序列、建议 TTL。
4. **v1.0.3d 进程操作**：最终身份绑定、gone 取消、写前审计与重试队列。
5. **v1.0.3e 状态收口**：审计发布、质量排序、登录恢复、marker 契约和完整发布验证。
